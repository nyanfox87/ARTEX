# 漏洞多流量證據

漏洞詳情的「關聯流量」支援跨頁多選、用途和說明、排序及解除綁定。流量頁也可多選記錄，一次關聯到一個已有漏洞。任務繼承的漏洞證據只讀，修改需進入來源任務。

系統設定中的「Agent 自動綁定流量」預設關閉，讀取和修改介面為 `/api/settings` 的 `agent_traffic_binding`。開啟會增加查閱請求/回應、工具呼叫及提示詞帶來的 Token 消耗；下一輪 Agent 使用新設定。關閉時隱藏自動綁定引數和補綁工具，不注入自動綁定指引，並拒絕已執行會話新提交的自動綁定。人工綁定、流量捕獲、已儲存證據讀取和匯出不受影響。

開啟後，預設流程是「發現入庫 → 自動觸發報告 Agent → 核對並綁定流量 → 按最新證據版本寫報告」。上報者在 `evidence` 保留驗證命令、關鍵輸出、已有真實流量 ID 及用途；報告 Agent 結合漏洞詳情和執行記錄，用 `traffic_search` / `traffic_get` 核實後呼叫 `bind_finding_traffic`，再讀取最新 `version` 儲存報告。關閉開關時，報告 Agent 不額外獲得原始流量檢索/讀取工具，也不自動綁定；仍能讀取人工綁定的快照並生成報告。

相容已有呼叫者：`report_finding` 的 `traffic_refs` / `evidence_hint_id` 仍可顯式即時綁定。綁定可選：TCP 等非 HTTP 漏洞、未採集或找不到確切記錄時，省略引用仍可正常上報和撰寫報告；保留命令輸出、日誌等其他可驗證證據，建議說明未綁定原因，不新增必填欄位。提交的 ID 必須全部有效且正文完整。任何一條失敗都會回滾本次綁定操作；顯式隨上報綁定失敗時整次上報回滾。重複追加同一快照不增加綁定，也不覆蓋說明。

## Agent 編號與報告版本

`report_finding` 新增可選引數，陣列順序即初始證據順序：

```json
{
  "traffic_refs": [
    {"traffic_id": "真實流量ID", "role": "baseline", "note": "正常賬戶請求"},
    {"traffic_id": "另一個真實流量ID", "role": "proof", "note": "重現請求"}
  ]
}
```

用途為 `baseline`（正常對照）、`proof`（漏洞證明）、`verification`（補充驗證）、`supporting`（輔助證據，預設）。先用 `traffic_search` / `traffic_get` 核對真實記錄；域名和時間僅用於候選篩選，不推定任務歸屬。

提示詞參考 [CyberStrikeAI 的漏洞上報工具指引](https://github.com/RuoJi6/CyberStrikeAI/blob/54d56774b8bd285817d16d48b70a4a5e6e0963f7/internal/app/vulnerability_tools.go)，結合本專案的可選綁定約定，不引入無包原因必填校驗。不得猜測 ID，也不應僅為補包重複探測。

返回第一行仍為 `finding recorded: <探索節點 ID>`；隨後 JSON 提供獨立漏洞記錄 `finding_id`、探索節點 `finding_node_id` 和綁定摘要。

- `get_finding_traffic(finding_id)` 使用**獨立漏洞記錄 ID**，返回有序清單及 `version`；傳 `binding_id`、`side=request|response`、`offset`、`length` 可分段讀取，每段最多 8192 位元組。
- `update_finding_report` 的 `finding_id` **繼續使用探索節點 ID**。新增 `evidence_version` 填實際讀取的版本；生成期間證據變化會拒絕舊版本寫入，必須重新讀取並生成。
- 舊報告呼叫未傳版本時，不宣稱覆蓋已有流量證據。綁定、說明、用途或排序變化後，已有報告提示待更新。

開啟自動綁定後，`add_hint` / `add_task_hint` 支援在單條提示或批次 `hints` 的每個元素中儲存 `traffic_refs`。Planner 代為上報可傳 `evidence_hint_id`，明確選取本任務對應提示中的引用，不能引用繼承提示。系統不會按域名、時間或瀏覽記錄猜測綁定。提交失敗不生成部分漏洞或提前觸發報告。

已有漏洞漏綁時可用 `bind_finding_traffic(finding_id, traffic_refs)` 補綁，無需重複登記。`list_findings` / `list_task_findings` / `node_detail` / `get_task_node_detail` 返回明確的 `finding_id` 和 `finding_node_id`；舊 `id` 保持探索節點語義。

啟動時僅為舊工具 schema 增加可選屬性，原始預設流量工具綁定擴充套件至報告 Agent；補綁工具預設交給報告 Agent。自定義綁定列表、提示詞、描述及啟用狀態保留。指引在最終工具裝配後統一加入：上報角色負責交接已有證據，報告 Agent 負責核對、綁定和寫報告。平臺對話缺少任務上下文時應通過結構化提示交接給任務 Agent，不直接上報。判定任務完成前應先交接已有證據；無包不強制等待。失敗的 `report_finding` 不觸發報告 Agent。

## API

基礎路徑：`/api/exploration/findings/{finding_id}/traffic`，使用獨立漏洞 ID。沿用認證；`context_task` 校驗任務可見性及繼承只讀。

| 方法 / 相對路徑 | 請求 / 返回 |
| --- | --- |
| `GET` | 有序摘要、證據版本、報告採用版本 |
| `POST` | `{"traffic_refs":[...]}` 整批追加 |
| `PATCH /{binding_id}` | `{"version":1,"role":"proof","note":"說明"}` |
| `DELETE /{binding_id}` | `{"version":1}` |
| `PUT /order` | `{"version":1,"binding_ids":["2","1"]}`，必須是完整列表 |
| `GET /{binding_id}` | 快照後設資料和有界正文預覽 |
| `GET /{binding_id}/body` | `side`、`offset`、`length`；`download=1` 下載完整原位元組 |

版本/排序集合衝突、歸檔中寫入返回 `409`；繼承寫入 `403`；不存在或不屬於漏洞的綁定 `404`；流量/附件讀取及校驗失敗明確返回錯誤。

## 儲存與遷移

啟動冪等遷移 PostgreSQL：新增 `traffic_evidence_snapshots`、`finding_traffic_bindings`，以及 `findings.evidence_version` / `report_evidence_version`（預設 0）。不根據歷史文字猜測補綁。

快照儲存原流量 ID、採集時間、URL、方法、狀態、請求/回應頭、正文長度和 SHA-256。正文按雜湊存放在 `<data>/evidence/blobs/<前兩位>/<hash>.bin`，與可清理的 `data/traffic` 獨立，多個漏洞可共享快照/正文。快照不提供內容更新介面，校驗不一致時讀取和匯出失敗。

在原流量寫鎖下讀取完整正文，包括大正文 blob 和舊目錄記錄。先持久化並校驗檔案，再用單個 PostgreSQL 事務寫入探索節點、意圖關係、漏洞、快照和綁定；提交後才通知規劃者。失敗可能遺留無引用檔案，但不產生部分業務記錄。

PostgreSQL advisory lock `7337741004` 協調證據檔案和 SQL 引用；任務行鎖禁止歸檔排隊後的證據修改。恢復從正文安裝到後設資料提交全程保持證據鎖。刪除漏洞級聯移除綁定。

清理器每小時執行，只回收無引用且非進行中操作的內容，至少延遲 24 小時。普通流量清理不觸及證據目錄。備份熱資料時同時備份 PostgreSQL 和 `data/evidence`。

## 匯出與歸檔

Markdown 包含有序證據清單及版本；JSON 包含後設資料；CSV 增加數量和綁定 ID。`md-zip` 保留漏洞 Markdown，並提供：

```text
evidence/<finding_id>/<binding_id>/
  manifest.json
  request.http
  response.http
  request.bin
  response.bin
```

Markdown 通過相對連結引用報文。傳送下載前完成附件複製、雜湊校驗、壓縮、磁碟同步及全部 ZIP 條目的 CRC 讀取校驗；缺失/損壞使整個下載失敗。完整附件保留二進位制原位元組。

歸檔 v3 按漏洞綁定關係收集快照和正文，不依賴原流量或域名。包校驗完成後才清理熱資料；共享證據繼續保留。恢復先校驗安裝正文，再事務恢復後設資料和綁定，支援失敗重試。v1/v2 繼續可恢復，缺失的新欄位顯式補為 0。

## 驗證與邊界

為每個測試包設定獨立、新建的 PostgreSQL 測試庫，通過 `ARTEX_PG_DSN` 指定，避免殘留任務/模型夾具觸發後臺執行。執行相關包完整測試，並確認沒有配置缺失導致的跳過：

```sh
# 每個包執行前將 ARTEX_PG_DSN 設為對應的獨立測試庫；顯式配置失敗必須報錯。
go test ./<package> -count=1
go test -race -p 1 ./evidence ./db ./agent ./server -run 'TestEvidence|TestFindingTraffic|TestFindingEvidence|TestReportFindingAtomicContract|TestTaskArchive'
```

前端驗證包含 `npx tsc --noEmit`、受影響檔案的 Biome 檢查、Webpack 構建和 `NEXT_EXPORT=1` 靜態匯出。使用獨立快取目錄，避免覆蓋執行中的開發服務。

本機端到端驗收使用獨立埠、受控 HTTP / 域名 HTTPS 目標和臨時資料目錄，覆蓋兩個綁定入口、跨頁選擇、排序/說明、錯誤提示、繼承只讀、下載，以及刪除原流量後匯出、歸檔、回收熱正文、恢復並校驗雜湊。

首版採用全域證據協調鎖；大批次綁定/匯出或慢速附件下載期間，其他證據操作可能等待。缺少錄製記錄或完整正文時不能補造證據。本功能不改變捕獲開關，也不處理 HTTPS 直接訪問 IP 的證書問題。
